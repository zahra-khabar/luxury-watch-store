# پروژه فروشگاه ساعت لوکس (Luxury Watch Store)

این پروژه یک API مبتنی بر **Django** و **Django REST Framework (DRF)** برای مدیریت یک فروشگاه ساعت لوکس است. هدف اصلی این تمرین، پیاده‌سازی یک دیتابیس کامل با استفاده از ORM و بهینه‌سازی کوئری‌ها برای جلوگیری از مشکل **N+1 Query** می‌باشد.

## 📁 ساختار و معماری پروژه

پروژه به گونه‌ای طراحی شده است که محیط **توسعه (Development)** و **پروداکشن (Production)** کاملاً از هم جدا باشند. این کار با استفاده از پکیج `python-dotenv` و ساختار ماژولار `settings` انجام شده است:

- `config/settings/base.py`: تنظیمات مشترک بین همه محیط‌ها (مانند `INSTALLED_APPS`).
- `config/settings/dev.py`: تنظیمات مخصوص توسعه (استفاده از دیتابیس `SQLite` و `DEBUG = True`).
- `config/settings/prod.py`: تنظیمات مخصوص سرور اصلی (استفاده از `PostgreSQL` و `DEBUG = False` به همراه تنظیمات امنیتی).
- `manage.py`: به صورت پیش‌فرض روی فایل `config.settings.dev` تنظیم شده است.

## 🛠 تکنولوژی‌های استفاده شده
- **Python 3.x**
- **Django & Django REST Framework (DRF)**
- **Django Debug Toolbar** (برای بررسی و آنالیز کوئری‌های دیتابیس)
- **Pillow** (برای مدیریت تصاویر)
- **Psycopg2** (برای اتصال به دیتابیس PostgreSQL در محیط پروداکشن)

## 🚀 بهینه‌سازی‌ها و حل مشکل N+1 Query

مشکل N+1 زمانی رخ می‌دهد که برای دریافت یک لیست (مثلاً ۱۰ محصول)، یک کوئری اصلی زده می‌شود و سپس برای دریافت اطلاعات مرتبط هر آیتم (مثلاً نام برند)، ۱۰ کوئری جداگانه دیگر به دیتابیس ارسال می‌شود. در این پروژه برای جلوگیری از این مشکل، از تکنیک‌های زیر استفاده شده است:

1. **استفاده از `select_related`:** 
   برای روابط `ForeignKey` (یک به چند). به عنوان مثال در `ProductListView` و `ProductDetailView` از `select_related('brand', 'category')` استفاده شده تا برند و دسته‌بندی در همان کوئری اولیه دریافت شوند.
   
2. **استفاده از `prefetch_related`:**
   برای روابط `ManyToMany` و روابط معکوس (Reverse ForeignKey). به عنوان مثال در `ProductDetailView` برای دریافت همزمان تصاویر، رنگ‌ها و کامنت‌های یک محصول از `prefetch_related('images', 'colors', 'comments__customer__user')` استفاده شده است.

3. **استفاده از `only()`:**
   در `LuxurySpecialView` از `only('title', 'price', 'gender', 'strap_material', 'engine')` استفاده شده تا فقط ستون‌های مورد نیاز از دیتابیس خوانده شوند و از بار اضافی جلوگیری شود.

4. **به‌روزرسانی اتمیک (Atomic Update):**
   برای افزایش تعداد کلیک (`click_count`) در `ProductDetailView` از `F('click_count') + 1` استفاده شده است. این کار نه تنها از مشکل N+1 جلوگیری می‌کند، بلکه از رخداد Race Condition در هنگام درخواست‌های همزمان نیز جلوگیری می‌کند (به جای خواندن مقدار و سپس آپدیت آن).

5. **محاسبه میانگین در سطح دیتابیس:**
   برای محاسبه میانگین قیمت محصولات لاکچری در `LuxurySpecialView`، از `aggregate(Avg('price'))` استفاده شده است تا محاسبات سنگین توسط خود دیتابیس (و نه پایتون) انجام شود.

> **نکته:** در برخی از بخش‌های بهینه‌سازی کوئری‌ها و ساختاردهی متدها، از هوش مصنوعی (AI) برای پیدا کردن بهترین و بهینه‌ترین روش‌ها (مانند انتخاب بین `aggregate` و `annotate`، یا چینش صحیح `prefetch_related`) استفاده شده است تا کدها استاندارد و بهینه‌ترین عملکرد را داشته باشند.
